## 로그추적기
### CH.1
#### 1. 로그추적기가 필요한 이유
- 원인을 찾기 어려울 수 있음 메소드 호출과 응답을 기록하면 예외가 발생한 지점이나 성능 병목을 쉽게 확인 가능
#### 2. 호출-응답 기록과 흐름 보존
- 컨트롤러, 서비스, 레파지토리처럼 여러 계층을 거치는 요청을 따라가며 각 메소드의 호출과 응답 기록. 정상 흐름뿐 아니라 예외 흐름도 구분해야 함
- 로그 처리 때문에 애플리케이션 로직의 흐름이 바뀌면 안됨
#### 3. 로그 추적기의 핵심 요구사항
- 모든 퍼블릭 메소드의 호출과 응답 기록
- 메소드별 실행 시간을 측정
- 로그 기록 과정이 비즈니스 로직에 영향을 주지 않는 것이 핵심
#### 4. 메소드 호출 깊이 표현
- 호출 관계를 계단식으로 표현하고 1, 2, 3처럼 레벨을 표시하면 현재 메소드가 호출 구조에서 어느 깊이에 있는지 파악 가능
#### 5. HTTP 요청을 구분하는 트랜잭션 아이디
- 여러 요청이 동시에 들어오면 로그가 섞일 수 있으므로 각 HTTP 요청에 아이디를 부여해 요청에서 시작된 로그를 구별
  - **DB 트랜잭션이 아닌 HTTP 요청**이 시작해서 끝날 때까지를 논리적으로 부르는 개념

```java

//예외 요청

[b7119f27] |   |<x-OrderRepository.save() time=0ms ex=java.lang.IllegalStateException: 예외 발생!
```
